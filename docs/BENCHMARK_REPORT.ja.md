## 実機観察とアーキテクチャ検証結果

1. **CPU オーバーヘッド**:
   - 常駐デーモンは極めて軽量に維持されています。ハードウェアデコード機能により、デコード処理が専用の NVIDIA NVDEC ASIC へオフロードされ、CPU 負荷が最小限に抑えられています。
2. **メモリフットプリント (RSS)**:
   - メモリ消費量は予測可能な境界内に安定して収まっています。4K 解像度のデュアル同時再生時であっても RSS はコンパクトに維持され、長時間のループ再生サイクルにおいてもメモリリークはゼロであることが確認されました。
3. **GPU デコーダーオフロード**:
   - ハードウェアデコードは優先利用方針であり、ホスト環境に依存します。本検証環境（NVIDIA RTX 3080 / ドライバー 615.71.09 / GStreamer 1.28.7）において、`nvh264dec` によるアクティブなハードウェアデコードの動作と NVDEC のクリーンなスケーリングを実証。ハードウェアデコーダ未搭載環境ではソフトウェアデコードへ安全にフォールバックします。
4. **バイナリサイズ**:
   - 常駐デーモンのバイナリサイズはわずか **4.7 MB**（strip後 **3.3 MB**）であり、`libcosmic` GUI 依存を分離して軽量なバックグラウンドフットプリントを維持するという基本設計方針を完璧に達成しています。
5. **初回正規化変換と2回目以降の再生特性**:
   - **適合規格動画 (MP4 コンテナ + H.264/yuv420p/30fps)**: トランスコード処理を完全にバイパスし、即時（0.1 秒未満）に永続ストレージへ配置されて再生開始します（CPU 負荷スパイクなし）。MKV や WebM 等の非MP4コンテナは、映像が H.264 であっても MP4 への正規化が実行されます。
   - **規格外動画 (HEVC/60fps/MKV等) の初回処理**: 初回指定時のみ ffmpeg による H.264/30fps 変換が走るため、一時的に CPU 全コア利用率が上昇しファンが回転します。ただし非同期ワーカースレッドで実行されるため、変換中も既存の壁紙は途切れることなく再生され続け、黒画面は発生しません。
   - **2回目以降の再生**: 永続ストレージ (`~/.local/share/fluffy/storage`) に保存された動画が即座に再利用されるため、CPU 負荷スパイク・ファン騒音・待ち時間ゼロでスムーズに再生されます。
