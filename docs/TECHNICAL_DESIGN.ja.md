## 1. 目的

本プロジェクトは、Wayland 環境の COSMIC Desktop 向けに軽量な動画壁紙マネージャーを提供します。

システムは意図的に以下の 2 つのプロセスに分離されています：

1.  **壁紙デーモン (Wallpaper daemon)**
    -   常時稼働（常駐プロセス）。
    -   Wayland layer-shell サーフェスを所有。
    -   GStreamer による動画再生パイプラインを所有。
    -   軽量な Unix ドメインソケット IPC インターフェースを公開。
    -   GUI ツールキットを一切含まない（フットプリント極小化）。
2.  **設定 GUI (Settings GUI)**
    -   オンデマンドで起動される一時的なクライアント。
    -   `libcosmic` を用いて構築。
    -   IPC 経由でデーモンと通信。
    -   設定適用後はユーザーが自由に終了可能。
    -   設定 GUI を閉じても動画再生は一切中断されず継続。

------------------------------------------------------------------------

## 2. 中核要件

### 必須要件

1.  動画のループ再生を継続して維持すること。
2.  デスクトップ操作（ウィンドウの移動、リサイズ、アプリ起動等）を阻害しないこと。
3.  同一動画内でのループ境界において、黒画面フラッシュ、もたつき、フレーム落ちが発生しないこと。
4.  動画の切り替え時（A ➔ B）に、黒画面やちらつきを発生させないこと。
5.  設定 GUI が閉じられても動画再生が継続すること。
6.  GUI を開かずに CLI から動画の変更、一時停止、再開、停止、ステータス取得が行えること。
7.  COSMIC デスクトップのネイティブな静止画壁紙を破壊・上書きしないこと。
8.  ハードウェアデコード（NVDEC / VA-API 等）を自動利用し、アイドル時の CPU 負荷を極小に保つこと。
9.  4K 解像度（3840x2160）以下の動画のみを許可し、過大な動画を安全に弾くこと。
10. マルチモニター環境において、各画面が独立して再生・制御できること。
11. systemd `--user` サービスとして起動・再起動・管理できること。

## 4. 非破壊オーバーレイモデル

### 4.1 基本方針

Fluffy は、COSMIC のネイティブ壁紙システム `cosmic-bg` と安全に共存します。

-   `cosmic-bg` は `Layer::Background` に静止画壁紙を描画します。
-   Fluffy は `Layer::Bottom`（パネルやドック、ウィンドウより下で、Background より上）にサーフェスを配置します。
-   ネイティブ壁紙ファイルを置換したり、`cosmic-bg` を kill することは一切ありません。
-   Fluffy が停止または異常終了した場合、サーフェスが Wayland プロトコルにより自動破棄され、元の静止画壁紙が即座にデスクトップ上に現れます。

## 5. プロセス境界とライフサイクル

### 5.1 プロセス分離

``` text
+-----------------------------+       +-----------------------------+
|     fluffy (デーモン)        |       |    fluffy-settings (GUI)    |
|                             |       |                             |
| - 常駐プロセス               |       | - 一時プロセス (オンデマンド)|
| - Wayland 接続保持          |  IPC  | - libcosmic アプリケーション |
| - GStreamer パイプライン所有 | <===> | - ファイルピッカー呼び出し  |
| - メモリ: ~40 MB RSS (Idle) |       | - デーモン状態の閲覧・操作  |
| - バイナリ: 3.2 MB          |       | - 終了しても再生に影響なし  |
+-----------------------------+       +-----------------------------+
```

### 5.2 ライフサイクル管理
- デーモンの推奨起動形態は `systemd --user` (`fluffy.service`)。
- デスクトップ環境のログイン時に自動起動し、セッション終了時に SIGTERM によりクリーンに終了。
- GUI はデスクトップランチャーまたは `fluffy-settings` コマンドから随時起動可能。

## 6. 状態モデル

各出力（モニター）ごとに以下の状態マシンを独立して管理します：

``` text
[Uninitialized]
       |
       v init_output()
    [Stopped] <---------------------+
       |                            |
       | play(video)                | stop()
       v                            |
   [Playing] -----------------------+
     |   ^                          |
     |   | resume()                 |
     |   v                          |
    [Paused] -----------------------+
```

- **Stopped**: サーフェスは存在しますが、再生パイプラインは停止中（背景は透明または直前の維持フレーム）。
- **Playing**: GStreamer パイプラインが `PLAYING` 状態で動作し、EOS 到達時は自動シークでループ。
- **Paused**: パイプラインが `PAUSED` 状態で静止フレームを維持。

------------------------------------------------------------------------

## 7. Wayland / レイヤーシェル仕様

- **プロトコル**: `zwlr_layer_shell_v1`
- **対象レイヤー**: `Layer::Bottom`
- **アンカー設定**: 上・下・左・右の全方向アンカー（出力全域を隙間なく被覆）
- **キーボード対話**: `KeyboardInteractivity::None`（一切の入力フォーカスを奪わない）
- **初期バッファ**: 親サーフェスに初期透明バッファ (`Argb8888`) を明示的にアタッチし、GStreamer の `waylandsink` が生成するサブサーフェスをコンポジターに確実にマッピング。

------------------------------------------------------------------------

## 8. 再生アーキテクチャ

### 8.1 デュアルパイプライン・プリロール切替

単一のパイプラインで `set_state(READY)` や URI 変更を行うと、`waylandsink` が一時的にバッファを解放し、黒画面がフラッシュします。

Fluffy では以下のアーキテクチャを採用しています：

``` text
[現行パイプライン A (PLAYING)] =====> [Wayland レイヤーサーフェス]
                                            ^
1. 新規パイプライン B を生成・プリロール開始     |
2. パイプライン B が PAUSED 状態で準備完了   |
3. パイプライン B を PLAYING へ遷移 =========+ (即座に切り替え)
4. 旧パイプライン A を停止・安全に破棄
```

これにより、切り替え時も 1 フレームの黒画面・ちらつきもなくシームレスに新しい動画へ移行します。

### 8.2 EOS ループシーク
動画終端（`GST_MESSAGE_EOS`）受信時、パイプラインの再生成は行わず、`seek_simple(0)` を発行して先頭へ巻き戻します。これによりデコーダの破棄・再構築オーバーヘッドをゼロに抑えています。

## 9. IPC 仕様

- **通信媒体**: Unix ドメインソケット (`$XDG_RUNTIME_DIR/fluffy.sock`)
- **パーミッション**: `0600` (実行ユーザーのみアクセス可能)
- **形式**: JSON Lines (改行区切り JSON)
- **制限事項**: 1 リクエスト最大 64 KB
- **世代セマンティクス**: モニターごとに `generation` カウンタを保持。クライアントが古い世代番号を指定した変更リクエストは安全に拒否。

------------------------------------------------------------------------

## 10. リクエスト / レスポンススキーマ

### コマンド一覧
- `status`: デーモン全体の稼働状態および全ディスプレイの個別状態を取得。
- `set-video`: 指定ディスプレイ（または全ディスプレイ）の壁紙動画を変更。
- `pause`: 再生を一時停止。
- `resume`: 再生を再開。
- `stop`: 再生を停止。
- `reload`: 現在の動画を再読み込み。

## 11. 永続ストレージと動画正規化

### 11.1 永続ストレージ構造 (`~/.local/share/fluffy/storage`)
変換済みおよび登録済みの動画ファイルは、OSやキャッシュクリーナーによって勝手に破棄されないよう、一時ディレクトリ（`~/.cache`）ではなく **XDG データディレクトリ内の永続ストレージ** に保存されます：
- **動画ファイル**: `$XDG_DATA_HOME/fluffy/storage/videos/<sha256>.mp4`（既定: `~/.local/share/fluffy/storage/videos/`）
- **メタデータ**: `$XDG_DATA_HOME/fluffy/storage/metadata/<sha256>.json`
- **永続性保証**: ユーザーが手動または設定ツールから明示的に削除するまで恒久的に保持されます。
- **原子的ファイル生成**: 一時ファイル (`.tmp.*`) に書き出した後、`fs::rename` によるアトミック移動を実施。

### 11.2 適合動画規格とトランスコード・バイパス
以下の規格を満たす動画ファイルは、**重いエンコード処理（ffmpeg）を完全にバイパス**し、瞬時にストレージへコピー/リンクされて即座に再生されます（CPU負荷・ファン回転ゼロ）：
- **コンテナ形式**: MP4
- **映像コーデック**: H.264 (`h264`, `avc1`)
- **色空間**: `yuv420p`
- **解像度**: 偶数ピクセル幅・高さ、かつ 4K 以下 (3840×2160)
- **フレームレート**: 30 fps 以下
- **音声処理**: プレーヤー側で自動ミュート（`fakesink`）されるため音声トラックの有無を問わずバイパス可能

### 11.3 規格外動画の非同期バックグラウンド正規化
HEVC/H.265, AV1, VP9, 60fps超、奇数解像度などの規格外動画は、初回指定時に自動正規化されます：
- **非同期ワーカースレッド実行**: メインスレッドから切り離されたワーカーで ffmpeg（`libx264`, `yuv420p`, 30fps）変換を実行。
- **黒画面ゼロ保証**: 変換処理中もデーモンのメインスレッド（Wayland イベント処理および GStreamer バスイベント処理）は停止せず、**現在の壁紙（前の動画またはデスクトップ壁紙）が滑らかに再生され続けます**。
- **初回負荷と2回目以降の高速性**: 初回のみ変換計算のため CPU 負荷と所要時間（ファン回転）が発生しますが、一度変換された動画は永続ストレージに保存されるため、**2回目以降はトランスコードなしでスムーズに即座に再生**されます。
- **リアルタイム通知・インジケーター**: `fluffy-settings` では回転する歯車/矢印アニメーションと案内が表示され、CLI の `fluffy status` でも進行状況が確認できます。


------------------------------------------------------------------------

## 12. 4K バリデーションポリシー

システムリソース保護のため、入力動画に対して以下の検証ルールを厳格に適用します：
- 最大幅: **3840 ピクセル**
- 最大高さ: **2160 ピクセル**
- 5K や 8K などの過大な動画ファイルは、トランスコード前に即座にエラーとして弾かれます。

------------------------------------------------------------------------

## 13. マルチモニターポリシー

- 接続されている各ディスプレイ（`DP-1`, `DP-2`, `HDMI-A-1` 等）を自動検出。
- ディスプレイごとに独立したサーフェスと再生パイプラインを割り当て。
- `fluffy set-video <PATH>` で全モニター同時適用。
- `fluffy set-video <PATH> --output DP-2` で特定モニターのみ個別適用。
- 画面のホットプラグ（接続・切断）イベントを自動追従。

------------------------------------------------------------------------

## 15. GUI の責務

`fluffy-settings` は以下の役割のみを担当します：
- 動画ファイルの選択とネイティブピッカーの提供
- キャッシュへのインポート進捗・バリデーション結果の表示
- 各ディスプレイの状態確認と対象選択
- IPC 経由でのコマンド送信

GUI プロセスはレイヤーサーフェスや GStreamer パイプラインを直接所有しません。

## 16. systemd --user 統合

- **サービスファイル**: `~/.config/systemd/user/fluffy.service`
- **ターゲット連携**: `WantedBy=graphical-session.target`, `PartOf=graphical-session.target`
- **再起動ポリシー**: `Restart=on-failure`, `RestartSec=3`

------------------------------------------------------------------------

## 17. エラー処理

エラーカテゴリ：
- `WaylandError`: ディスプレイ接続やサーフェス生成の失敗
- `PlaybackError`: GStreamer パイプライン構築や再生エラー
- `IpcError`: ソケット通信、シリアライズ、古い世代番号の拒否
- `CacheError`: キャッシュディレクトリのアクセス権やファイル破損
- `ProbeError`: `ffprobe` 解析失敗、4K 境界超過
- `NormalizeError`: `ffmpeg` 変換失敗

------------------------------------------------------------------------

## 18. セキュリティ / 信頼境界

- Unix ソケットパーミッションを `0600` に制限し、他ユーザーからのアクセスを遮断。
- IPC メッセージおよび動画パスは安全にエスケープ・検証し、シェル展開 (`sh -c`) を一切行わず直接引数配列として実行。
- パストラバーサル防止のため、ファイルパスを安全に正規化 (`canonicalize`)。

## 22. 既知のリスクと対応策

- **GStreamer/Wayland 結合**: 親サーフェスへの初期ベースバッファ供給により完全解決。

## 23. 明示的な非ゴール (v1)

初期バージョンでは以下の機能は意図的にスコープ外としています：
- 音声再生（壁紙用途のため無音）
- 字幕表示
- 複雑なプレイリスト機能
- ネットワークストリーミング再生
- 8K 動画のサポート
- 60fps 既定再生（省電力のため 30fps を基本）
